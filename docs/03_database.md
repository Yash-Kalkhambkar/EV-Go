## Tables

### users

```sql
CREATE TABLE users (
    id            BIGSERIAL PRIMARY KEY,
    full_name     VARCHAR(100)        NOT NULL,
    email         VARCHAR(255)        NOT NULL UNIQUE,
    password_hash VARCHAR(255)        NOT NULL,
    role          VARCHAR(20)         NOT NULL DEFAULT 'USER',  -- USER | ADMIN
    phone         VARCHAR(20),
    created_at    TIMESTAMPTZ         NOT NULL DEFAULT NOW(),
    updated_at    TIMESTAMPTZ         NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_users_email ON users(email);
```

`role` is stored as a plain string, mapped to `Role` enum in Java. Kept simple — no separate roles table needed for v1.

### stations

```sql
CREATE TABLE stations (
    id              BIGSERIAL PRIMARY KEY,
    name            VARCHAR(150)    NOT NULL,
    address         VARCHAR(300)    NOT NULL,
    latitude        DECIMAL(9,6)    NOT NULL,
    longitude       DECIMAL(9,6)    NOT NULL,
    description     TEXT,
    total_slots     INT             NOT NULL DEFAULT 0,  -- Physical charger count, not time slots
    price_per_hour  DECIMAL(8,2)    NOT NULL,
    is_active       BOOLEAN         NOT NULL DEFAULT TRUE,
    created_at      TIMESTAMPTZ     NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ     NOT NULL DEFAULT NOW()
);

-- PostGIS-style proximity search without full PostGIS extension
-- Using basic lat/lng bounding box first, then Haversine in app layer
CREATE INDEX idx_stations_location ON stations(latitude, longitude);
CREATE INDEX idx_stations_active ON stations(is_active) WHERE is_active = TRUE;
```

**Note on `total_slots`:** This field represents the number of physical charging ports at the station (how many cars can charge simultaneously), not the count of generated time slot records. For example, a station with 8 physical chargers might have `total_slots = 8`, but hundreds of slot records in the `slots` table (8 chargers × multiple time slots per day × multiple days).

### connector_types

Stores which connector types each station supports. A station can have multiple.

```sql
CREATE TABLE connector_types (
    id              BIGSERIAL PRIMARY KEY,
    station_id      BIGINT          NOT NULL REFERENCES stations(id) ON DELETE CASCADE,
    connector_type  VARCHAR(50)     NOT NULL   -- validated string, backed by Java enum: CCS2 | TYPE2 | CHADEMO | GB_T
);

CREATE INDEX idx_connector_station ON connector_types(station_id);
```

**Note:** The `connector_type` column stores string values validated against a Java enum (`CCS2`, `TYPE2`, `CHADEMO`, `GB_T`). Validation happens at the API/DTO boundary to ensure only valid connector types are persisted.

### slots

Each row is a specific bookable time slot at a station. Slots are generated by the admin when setting up or updating a station.

```sql
CREATE TABLE slots (
    id          BIGSERIAL PRIMARY KEY,
    station_id  BIGINT          NOT NULL REFERENCES stations(id) ON DELETE CASCADE,
    slot_date   DATE            NOT NULL,
    start_time  TIME            NOT NULL,
    end_time    TIME            NOT NULL,
    status      VARCHAR(20)     NOT NULL DEFAULT 'AVAILABLE',  -- AVAILABLE | RESERVED | BOOKED | UNAVAILABLE
    created_at  TIMESTAMPTZ     NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ     NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_slots_station_date ON slots(station_id, slot_date);
CREATE INDEX idx_slots_status ON slots(status);

-- Prevent duplicate slots for same station + date + time
ALTER TABLE slots ADD CONSTRAINT uq_slot UNIQUE (station_id, slot_date, start_time);
```

**Slot status lifecycle:**
```
AVAILABLE → RESERVED (Redis lock acquired + booking record created)
RESERVED  → BOOKED   (payment confirmed by Razorpay webhook)
RESERVED  → AVAILABLE (payment failed / timeout, lock released)
BOOKED    → AVAILABLE (booking cancelled by user, if allowed)
AVAILABLE → UNAVAILABLE (admin disables a slot)
```

### bookings

```sql
CREATE TABLE bookings (
    id              BIGSERIAL PRIMARY KEY,
    user_id         BIGINT          NOT NULL REFERENCES users(id),
    slot_id         BIGINT          NOT NULL REFERENCES slots(id),
    station_id      BIGINT          NOT NULL REFERENCES stations(id),
    status          VARCHAR(20)     NOT NULL DEFAULT 'PENDING',  -- PENDING | CONFIRMED | CANCELLED | COMPLETED
    total_amount    DECIMAL(8,2)    NOT NULL,
    razorpay_order_id VARCHAR(100),
    booked_at       TIMESTAMPTZ     NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ     NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_bookings_user ON bookings(user_id);
CREATE INDEX idx_bookings_slot ON bookings(slot_id);
CREATE INDEX idx_bookings_status ON bookings(status);

-- A slot can only have one non-cancelled booking at a time
CREATE UNIQUE INDEX uq_active_booking ON bookings(slot_id)
    WHERE status NOT IN ('CANCELLED');
```

**Booking status lifecycle:**
```
PENDING → CONFIRMED  (Razorpay payment verified)
PENDING → CANCELLED  (payment failed or user cancelled before paying)
CONFIRMED → CANCELLED (user cancels — subject to cancellation policy)
CONFIRMED → COMPLETED (slot time has passed)
```

### payments

```sql
CREATE TABLE payments (
    id                  BIGSERIAL PRIMARY KEY,
    booking_id          BIGINT          NOT NULL REFERENCES bookings(id),
    razorpay_order_id   VARCHAR(100)    NOT NULL,
    razorpay_payment_id VARCHAR(100),   -- filled after successful payment
    razorpay_signature  VARCHAR(255),   -- for verification
    amount              DECIMAL(8,2)    NOT NULL,
    currency            VARCHAR(10)     NOT NULL DEFAULT 'INR',
    status              VARCHAR(20)     NOT NULL DEFAULT 'CREATED',  -- CREATED | SUCCESS | FAILED
    created_at          TIMESTAMPTZ     NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ     NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_payments_booking ON payments(booking_id);
CREATE INDEX idx_payments_razorpay_order ON payments(razorpay_order_id);
```

## JPA Entities (Java)

```java
// Station.java
@Entity
@Table(name = "stations")
public class Station {
    @Id @GeneratedValue(strategy = IDENTITY)
    private Long id;

    private String name;
    private String address;
    private BigDecimal latitude;
    private BigDecimal longitude;
    private String description;
    private int totalSlots;
    private BigDecimal pricePerHour;
    private boolean isActive;

    @OneToMany(mappedBy = "station", cascade = ALL, fetch = LAZY)
    private List<ConnectorType> connectorTypes;

    @OneToMany(mappedBy = "station", cascade = ALL, fetch = LAZY)
    private List<Slot> slots;

    @CreationTimestamp private Instant createdAt;
    @UpdateTimestamp private Instant updatedAt;
}

// Slot.java
@Entity
@Table(name = "slots")
public class Slot {
    @Id @GeneratedValue(strategy = IDENTITY)
    private Long id;

    @ManyToOne(fetch = LAZY)
    @JoinColumn(name = "station_id")
    private Station station;

    private LocalDate slotDate;
    private LocalTime startTime;
    private LocalTime endTime;

    @Enumerated(EnumType.STRING)
    private SlotStatus status;

    @CreationTimestamp private Instant createdAt;
    @UpdateTimestamp private Instant updatedAt;
}

// Booking.java
@Entity
@Table(name = "bookings")
public class Booking {
    @Id @GeneratedValue(strategy = IDENTITY)
    private Long id;

    @ManyToOne(fetch = LAZY) @JoinColumn(name = "user_id")
    private User user;

    @ManyToOne(fetch = LAZY) @JoinColumn(name = "slot_id")
    private Slot slot;

    @ManyToOne(fetch = LAZY) @JoinColumn(name = "station_id")
    private Station station;

    @Enumerated(EnumType.STRING)
    private BookingStatus status;

    private BigDecimal totalAmount;
    private String razorpayOrderId;
    private Instant bookedAt;
    private Instant updatedAt;
}
```

## Proximity Search (without PostGIS)

For finding nearby stations, the backend uses a bounding box query in Postgres + Haversine distance calculation in Java:

```java
// StationRepository.java
@Query("""
    SELECT s FROM Station s
    WHERE s.latitude BETWEEN :minLat AND :maxLat
    AND s.longitude BETWEEN :minLng AND :maxLng
    AND s.isActive = true
""")
List<Station> findWithinBoundingBox(
    @Param("minLat") BigDecimal minLat,
    @Param("maxLat") BigDecimal maxLat,
    @Param("minLng")  BigDecimal minLng,
    @Param("maxLng")  BigDecimal maxLng
);
```

The bounding box is computed from the user's location + radius in `StationService`. After fetching results, Haversine distance is calculated in Java and used to sort by actual distance. This avoids the PostGIS dependency while being accurate enough for v1.

For v2, if station counts grow large, switch to PostGIS `ST_DWithin` with a spatial index.
